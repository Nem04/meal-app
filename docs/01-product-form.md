# 家庭点菜小程序 · 产品形态与功能规划

> 日期：2026-11-02 | 版本：v1.0（草案）
> 目标人群：2 人家庭，极简、零学习成本，家人随手可用。

## 1. 一句话定位

> 一张「今天吃什么」的线上菜单：有人开饭、有人点菜，食材自动合并去重、对着库存看缺什么，吃完留一句话，月底翻月历就知道这个月都吃了些什么。

## 2. 产品形态决策

| 决策项 | 结论 |
|--------|------|
| 交付形态 | **第一阶段：手机网页版（PWA）**，界面/交互尽量复刻微信小程序观感 |
| 未来演进 | 保留「套壳成真微信小程序」可能（C 选项）：核心后端与页面结构解耦，前端用可迁移的技术栈 |
| 使用入口 | 手机浏览器打开本地地址/二维码；局域网 `http://<家用设备IP>:端口`，远程通过内网穿透/公网链路访问 |
| 登录权限 | 不做注册登录、不做复杂权限。以「家庭信任模式」运行，可选一个 4 位家庭口令做最轻的隔离 |
| 设备形态 | 手机为主（触屏第一优先），桌面浏览器兼容查看 |

### 1.1 为什么「网页版先行」

- **零审核**：不需要微信小程序账号、服务器域名备案、HTTPS 强制证书。
- **零/低成本**：家庭自用不产生额外云费用。
- **当天能跑**：一台常开设备 + 一个二维码即可全家使用。
- **可升级**：后端 API 不变，前端可后续套壳成小程序，不推倒重来。

### 1.2 部署拓扑（第一阶段）

```
[手机A]──┐
[手机B]──┼──► 家用常开设备（树莓派/群晖/软路由/旧电脑/电脑）
            │
            ├─ 运行：NestJS/Express 后端 + SQLite 数据库
            └─ 可选：内网穿透（Tailscale / Cloudflare Tunnel / frp）实现远程访问
```

- **局域网优先**：IP + 端口即可，无需域名。
- **远程可选**：不改变任何业务逻辑，只加一层网络通道。

## 3. 核心功能模块总览

| 模块 | 核心动作 | 一句话体验 |
|------|----------|------------|
| 点菜 | 主厨开饭 → 家人选菜 → 提交 → 合并食材 | 三道菜都要葱，合并成「葱 3 根」而不是三条葱 |
| 备菜 | 合并后的食材按菜对照库存 → 缺什么一目了然 | 勾选只代表「备齐了」，绝不悄悄扣库存 |
| 库存 | 粘贴式录入、批量增减 | 「芹菜一斤，酱油一瓶、鸡蛋十个」直接粘进去 |
| 菜谱 | 浏览/搜索、加入菜单、另存为自家版本改 | 一道菜两副面孔：大众版 + 我家版 |
| 日志 | 吃完全家留一句话 + 月历回顾 | 月历亮起点点，一眼看见这个月吃了哪些 |

### 3.1 五个模块的内部关系

```
菜谱 ──选菜──► 一顿饭(点菜) ──合并食材──► 备菜 ──对照──► 库存
                                              │
                                              └─ 勾选「备齐」仅为状态，不动库存
每顿饭 ──吃完全家留一句话──► 日志 ──聚合──► 月历
```

关键规则（产品红线，后文全部据此设计）：

1. **合并规则**：同名称 + 同单位（或可换算单位）的食材合并，不同单位保留两部分并在备菜时提示「可换算」。
2. **库存不自动扣减**：库存变化只发生在「手动入库/出库/盘点」三种显式动作。
3. **备菜勾选不碰库存**：勾选只是给主厨看的「这格已备齐」进度，写完不会改库存表。
4. **不推断保质期**：库存只有「名称 + 数量 + 单位 + 备注」，没有也无须过期提醒。

## 4. 角色与使用链路

### 4.1 角色（家庭模式，非硬性账号）

- **主厨（Host）**：负责开饭、看合并食材、对照库存备菜、结束后关门。
- **家人（Guest）**：负责看到「有一顿饭在开」后选菜、提交。

2 人家庭里，两个角色是「同一个人分时扮演」，不需要区分登录。

### 4.2 典型一天链路

1. 主厨打开 App → 新建一顿饭「今晚」。
2. 主厨从「菜谱」勾入：红烧肉、番茄炒蛋、凉拌黄瓜。
3. 家人手机点开同一地址 → 看到「今晚这顿饭」→ 想加一道 → 提交「清蒸鱼」。
4. 主厨查看「合并食材」：红烧肉 + 清蒸鱼 + 番茄炒蛋 + 凉拌黄瓜 的食材自动按菜和总量合并去重。
5. 主厨进入「备菜」：食材按菜展开，对照库存显示「缺：葱 2 根、生抽 半瓶」。
6. 主厨去超市/冰箱补货，回来逐项勾选「备齐了」。
7. 主厨手动把这次买的东西录进库存（可选，库存不自动变）。
8. 吃完饭，留一句话「今天红烧肉绝了」。
9. 月底点「日志」，月历上看到每次开饭和那句话。

## 5. 不做什么（V1 明确排除，避免范围蔓延）

- ❌ 不做复杂账号体系、好友邀请、家庭群组管理（2 人家庭信任模式）。
- ❌ 不自动扣减库存、不做保质期/临期提醒。
- ❌ 不做营养/卡路里计算。
- ❌ 不做下单支付、外卖、电商。
- ❌ 不做语音/拍照识别选菜（后续可议）。
- ❌ 不做多家庭隔离（单一个「家」）。
- ❌ V1 不做真微信小程序注册发布（保留演进接口即可）。

## 6. 成功标准（自用验收口径）

- 家人用手机在 30 秒内完成「看到饭 → 选菜 → 提交」。
- 三道菜都要葱时，备菜页只出现一条合并后的葱，不出现三条。
- 粘贴一段库存文本，能一次生成多条库存记录。
- 备菜勾选后，库存数量不发生变化（可被验证）。
- 月历能准确罗列本月吃过的每一顿饭和那句话。
- 全程无需注册登录即可使用（局域网内）。
