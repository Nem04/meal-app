# 家庭点菜小程序 · 实施开发计划

> 版本：v1.0（草案） | 日期：2026-11-02
> 前置：需求文档 `02-requirements.md`、后端架构 `04-backend-architecture.md` 已评审。

## 0. 总原则

- **里程碑驱动**，每个里程碑可独立交付、可手动验收。
- **先打通一条「今晚点菜」主链路**（M1–M2），再补库存/菜谱/日志。
- 每阶段结束做一次红线测试（备菜勾选不扣库存、菜谱 fork 隔离、点菜去重）。

## 1. 里程碑总览

| 里程碑 | 内容 | 可交付结果 |
|--------|------|-----------|
| M0 | 项目骨架 + 数据库 + 基础 UI 壳 | 能跑的空壳，页面可切换 |
| M1 | 菜谱 CRUD（含 fork 我家版） | 菜谱可维护、可另存 |
| M2 | 开饭 + 点菜 + 合并去重 | 核心主链路可用 |
| M3 | 备菜对照库存 + 勾选备齐（不扣库存） | 主厨缺货清单 |
| M4 | 库存批量录入 + 手动增删改盘点 | 整段粘贴建档 |
| M5 | 日志 + 月历回顾 | 吃完全家留话、月底回看 |
| M6 | 美化 UI + PWA + 部署脚本 + 备份 | 可扫码使用、数据安全 |

## 2. 详细拆解

### M0 项目骨架（0.5–1 天）
- [ ] 初始化 monorepo：`backend` + `frontend` + `docs`。
- [ ] 后端脚手架：Node + TypeScript + Fastify/Express + Prisma(Drizzle) + SQLite。
- [ ] 建立数据模型 schema（第 4 节 9 张表）。
- [ ] 前端脚手架：Vite + Vue/React，移动端壳、底部 Tab、路由。
- [ ] CI 可选：本地 `pnpm test` 跑通。
- **验收**：手机访问首页能看到 4 个 Tab 骨架。

### M1 菜谱（1–2 天）
- [ ] Recipe / RecipeVersion / IngredientSpec API。
- [ ] 菜谱浏览、搜索、详情、新建。
- [ ] 「另存为我家版」fork 逻辑 + 测试（改副本不影响原版）。
- **验收**：可新建一道「番茄炒蛋」含食材，另存副本改食材后原版不变。

### M2 开饭 + 点菜 + 合并去重（2–3 天，核心）
- [ ] Meal / MealItem API。
- [ ] 开饭、从菜谱选菜、家人提交（upsert 去重）。
- [ ] **合并引擎**：别名规范化 + 单位归一化 + 聚合 + 跨单位提示。
- [ ] 合并清单展示（按菜 / 汇总切换）。
- **验收**：三道菜要葱 → 只有一条葱；同人重复提交不重复堆积。

### M3 备菜对照库存（1–2 天）
- [ ] 库存最小可用列表（M4 先做一个假数据入口或用临时 API）。
- [ ] MealPrepEntry 投影 + 对照库存求缺额。
- [ ] 勾选备齐 + ***红线单测：勾选前后库存快照一致***。
- **验收**：缺货红色置顶，备齐后库存不变。

### M4 库存（2–3 天）
- [ ] InventoryItem + InventoryLog。
- [ ] **解析引擎**：文本 → 三元组，正则 + 中文量词映射。
- [ ] 解析预览（`/inventory/parse`）+ 确认后批量入库（`/inventory/bulk`）。
- [ ] 手动加/减/盘点 + 变更日志。
- **验收**：「芹菜一斤，酱油一瓶、鸡蛋十个」一次入库 3 条；不自动扣减。

### M5 日志 + 月历（0.5–1 天）
- [ ] MealLog API（一句话 + 评分）。
- [ ] `/calendar?month=` 聚合。
- [ ] 月历 UI：每日小点 + 详情抽屉。
- **验收**：本月每顿饭与那句话可在月历看到。

### M6 收尾（1–2 天）
- [ ] UI 精修对照 `03-ui-style.md`。
- [ ] PWA 缓存 / 添加到主屏。
- [ ] 部署脚本：开机自启、防睡眠、局域网 IP 提示 + 二维码。
- [ ] 备份脚本（SQLite 自动备份 + JSON 导出）。
- [ ] 可选远程：Tailscale/Cloudflare Tunnel 接入说明。
- **验收**：家里手机扫码即可使用。

## 3. 红线测试清单（贯穿始终）

| 测试 | 断言 |
|------|------|
| T1 | 勾选备齐前后，库存表快照完全一致 |
| T2 | fork 我家版后修改副本，原版不变 |
| T3 | 同人同菜重复点菜 upsert 不新增行 |
| T4 | 合并清单对同一 canonical+unit 去重后仅一条 |
| T5 | 文本解析示例生成 3 条并落库 |
| T6 | 结束饭局后仍在月历可查 |
| T7 | 无任何代码路径自动写库存（代码评审确认） |

## 4. 里程碑验收口径（Definition of Done）

每个 M 合并前：

- [ ] 功能跑通（按 M 的验收）。
- [ ] 相关红线测试通过。
- [ ] UI 符合对应页面规格（M6 前允许低保真）。
- [ ] 更新本计划勾选项与文档。

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 文本解析中文量词复杂 | 录入不准 | 失败进待确认；逐步积累别名/量词表 |
| 单位换算误差 | 合并不彻底 | V1 不隐式换算，跨单位并排提示 |
| 常开设备断电/睡眠 | 服务不可用 | 防睡眠脚本 + 断电自启 + 备份 |
| 远程暴露风险 | 数据泄露 | 默认关远程；启用用口令/隧道 |
| 熟人误操作库存 | 数据错乱 | 库存变更日志 + 手动导出备份 |

## 6. 推荐下一步

1. 先确认四份文档是否合意（尤其合并规则、库存红线、菜谱 fork）。
2. 确认后进入 **M0 + M1**：我先搭骨架并实现菜谱模块，跑一个可点击的原型给你看。
3. 原型 OK 后，按 M2→M3→M4→M5→M6 顺序推进，每阶段给你可验收的版本。
