# 家庭点菜小程序 · 需求开发文档（PRD）

> 版本：v1.0（草案） | 日期：2026-11-02 | 状态：待确认
> 对应产品形态见 `01-product-form.md`。

## 1. 需求背景与目标

家庭日常吃饭存在反复沟通的成本：「今晚吃什么」「家里有葱吗」「你买的菜我重复买了吗」。本产品把「点菜—合并食材—对照库存—备菜—回顾」串成一条链，目标是 **把一顿饭的协作成本降到最低**，让主厨只做一次决策、家人只点一次菜。

### 1.1 北极星指标（自用版）

- **开饭到备菜完成的耗时**：一次开饭从建立到所有食材标注「备齐」的总时长。
- **重复食材条数**：合并前 n 类食材 → 合并后应约等于 1 条/（名称+单位）。理想目标是 0 余重复。
- **月历覆盖度**：本月已记录的饭局数 / 实际吃饭天数。

## 2. 用户与场景

| 用户 | 动机 | 核心诉求 |
|------|------|----------|
| 主厨 | 不买菜重复、不漏菜 | 合并后清单 + 库存对照 |
| 家人 | 不被反复问、能表达想吃什么 | 手机上轻松点选并看到已选 |
| 家庭 | 想留下「我们家吃了什么」 | 日志与月历回顾 |

### 2.1 用户故事（摘要）

- 作为主厨，我想开一顿饭并设定用餐时间，这样家人能集中在这一顿上点菜。
- 作为家人，我想在上面选菜并留一句备注（如「少放辣」），提交后主厨能看到。
- 作为主厨，我想看到按菜合并、按食材去重的最终清单，而不是三条一样的葱。
- 作为主厨，我想让食材对照库存，缺什么一眼能看到。
- 作为主厨，我想勾选「备齐」但不希望系统动我的库存。
- 作为主厨，我想把采购/盘点信息整段粘进库存，快速建档。
- 作为家人，我想把网上的菜谱存为「我家版本」随意改，而不破坏原版。
- 作为家庭，我想在月历上回看这个月都吃了什么、当时留了什么话。

## 3. 范围（Scope）

### 3.1 In Scope（V1）

- 开饭/点菜/合并食材核心链路。
- 备菜对照库存 + 勾选备齐。
- 库存批量录入、手动增删改、盘点。
- 菜谱浏览、加入菜单、另存为自家版本。
- 饭局日志 + 月历视图。
- 单家庭、局域网优先 + 可选远程访问。

### 3.2 Out of Scope（V1）

- 账号注册/多家庭隔离/微信登录。
- 库存自动扣减、保质期。
- 支付、外卖、购物清单导出分享（本地导出 CSV 可议）。
- 菜谱评论、点赞、公共社区。

## 4. 功能需求（按模块）

以下编号如 `MEAL-01` 用于后续开发追踪。

---

### 4.1 模块 A：开饭 / 点菜

#### MEAL-01 新建一顿饭
- **触发**：主厨在首页点「开一顿饭」。
- **输入**：饭名（默认「今晚」/「午餐」）+ 用餐日期 + 可选备注。
- **规则**：同一时间只允许有 ≤ 1 顿「进行中」的饭；其余为「已结束」归档。
- **验收**：创建后出现在「进行中」列表顶部；家人端可见。

#### MEAL-02 从菜谱选菜
- **触发**：主厨/家人在一顿饭详情里点「加一道菜」。
- **输入**：从菜谱库选择 1..n 道菜，可带一条个人备注。
- **规则**：选中的菜在饭局内可重复（同一道菜两人点则合并数量，见 MEAL-05 备注）。
- **验收**：选菜后该顿饭的「已选菜品」实时刷新，展示菜品 + 备注。

#### MEAL-03 提交点菜
- **触发**：家人确认要吃的菜，点「提交」。
- **输出**：主厨端的合并食材清单更新。
- **规则**：提交是「追加」语义，不是覆盖；同一家人重复提交需去重（按提交人最近一次有效选择）。
- **验收**：提交后本人看到「已提交」状态；主厨看到新增食材并入清单。

#### MEAL-04 食材合并去重
- **触发**：任何点菜提交后实时计算。
- **规则（核心红线）**：
  1. 以菜谱中每道菜的「食材表」为数据源展开。
  2. 识别食材的 **规范名称（canonical）** 与 **单位**：`葱`/`小葱`/`香葱` → `葱`；`2个`+`3个` → `5个`。
  3. 同一 canonical 相同单位 → 数量相加，只保留一条。
  4. 同一 canonical 不同单位（如 `斤` vs `克`）→ V1 保留两条但在 UI 上并排提示「可换算/是否合并」。
  5. 无法识别的新食材：原样保留为独立条目，并打「待归类」标。
- **验收**：三道菜都需要葱时，合并清单只出现一条葱；数量 = 三道菜之和。

#### MEAL-05 合并清单展示
- **分组**：按菜分组展示，最后给出「食材汇总」。
- **字段**：食材名 / 单菜用量 / 汇总量 / 库存可用量 / 缺额 / 备齐状态。
- **验收**：清单可一键展开/收起「按菜」与「只看汇总」两种视角。

---

### 4.2 模块 B：备菜

#### PREP-01 对照库存
- **触发**：进入备菜页。
- **规则**：对汇总清单中每个（canonical，单位）条目，查询当前库存中的可用量。
  - 缺额 = 需求 - max(库存, 0)；缺额 > 0 标红「缺」。
  - 库存 0 或缺失显示「无」。
- **验收**：缺的食材排在顶部并高亮；够的食材沉底。

#### PREP-02 勾选备齐（状态，不扣库存）
- **触发**：主厨勾选某条目「备齐了」。
- **规则**：仅更新该饭局的 `prepared` 状态；**任何条件下都不得写库存表**。
- **验收**：勾选后库存数量不变（可用测试断言验证：勾选前库存快照 == 勾选后库存快照）。

#### PREP-03 备菜进度
- **规则**：显示「已备齐 n / 共 m」；全部备齐后首页该顿饭标记「备齐 ✓」。

---

### 4.3 模块 C：库存

#### INV-01 批量录入
- **触发**：库存页点「录入/粘贴」。
- **输入**：自由文本，如「芹菜一斤，酱油一瓶、鸡蛋十个」。
- **规则**：
  - 以 `，、,；;\n` 一类分隔符分割为条目。
  - 每条解析为「名称 + 数量 + 单位」三元组；支持「一斤」「两个」「10个」「半瓶」「一瓶」「若干」。
  - 解析失败不丢弃，进入「待确认」二次校准界面。
- **验收**：示例文本生成 `芹菜 1 斤`、`酱油 1 瓶`、`鸡蛋 10 个` 3 条记录。

#### INV-02 库存增/删/改/盘点
- **规则**：
  - 手动加库存（入）、手动减库存（出）、直接改数量（盘点）是三种显式操作。
  - 不允许系统后台自动扣减；唯一可能的非手动作业是「入库导入」，仍需用户确认。
- **验收**：无任何接口/定时任务会写入库存数量；仅人力动作产生变更。

#### INV-03 库存名单
- **字段**：名称(canonical)、数量、单位、更新人、更新时间、备注。
- **规则**：不记录、不推断保质期。
- **验收**：列表可搜索、可按名称排序、可编辑数量。

---

### 4.4 模块 D：菜谱

#### REC-01 菜谱浏览/搜索
- **字段**：菜名、分类（荤/素/汤/主食/凉菜）、图示（可选）、食材列表、步骤、来源。
- **验收**：列表中可搜索「葱」，能返回所有含葱的菜。

#### REC-02 加入菜单
- **触发**：菜谱详情页「加入这顿饭」。
- **规则**：把菜谱挂在当前进行中的饭上。
- **验收**：饭局内出现该菜，并正确展开其食材参与合并。

#### REC-03 另存为自家版本
- **触发**：菜谱详情页「另存为我家版」。
- **规则**：复制原菜谱为一份可编辑副本，标记 `fork_of`；编辑副本不影响原版。
- **验收**：改我家版食材后，原菜谱不变；反之亦然。

#### REC-04 创建新菜谱
- **触发**：主厨手工录入/粘贴食材和步骤。
- **验收**：新菜谱可直接被「加入菜单」。

---

### 4.5 模块 E：日志 / 月历

#### LOG-01 留一句话
- **触发**：饭局结束（手动点「吃完了」）后可留一句话 + 可选评分（好吃/一般/踩雷）。
- **验收**：一句话与评分绑定到该饭局。

#### LOG-02 月历回顾
- **规则**：按用餐日期聚合；日历日期格内显示当日菜品摘要 + 一句话。
- **验收**：点某一格可看到当天吃的菜、那句话、谁提交的点菜备注。

## 5. 非功能需求（NFR）

| 编号 | 类别 | 要求 |
|------|------|------|
| N1 | 易用性 | 手机触控，关键按钮 ≥ 44px；核心链路 ≤ 30 秒完成 |
| N2 | 性能 | 局域网内列表加载 < 500ms；合并计算对 ≤ 50 道菜实时完成 |
| N3 | 数据一致性 | 备菜勾选绝不写库存（硬约束，单元测试覆盖） |
| N4 | 可用性 | 单机部署，重启后数据不丢（SQLite 持久化 + 备份导出） |
| N5 | 兼容 | iOS Safari / Android Chrome / 微信内置浏览器 |
| N6 | 安全 | 局域网内不强行鉴权；启用远程时可用家庭口令可选保护 |
| N7 | 可迁移 | API 与前端分享解耦，为将来套微信小程序壳预留 |

## 6. 关键业务规则清单（红线）

1. 合并去重以「规范名称 + 单位」为唯一键；知名别名需收敛到规范名称。
2. 勾选「备齐」只改饭局状态，永不写库存。
3. 库存不自动扣减、不推断保质期。
4. 菜谱「另存为我家版」是复制语义（copy-on-write），与原版解耦。
5. 点菜提交用「最近一次有效提交」去重，避免同一人重复堆积。
6. 饭后日志必须挂在某顿饭上，不孤悬。

## 7. 数据埋点 / 可观测（可选，自用）

- 记录每次「开饭 → 提交 → 备齐」的时间戳，便于月底看效率。
- 库存变更日志（谁、何时、加/减/盘、数量）以备误操作追溯。

## 8. 风险与开放问题

| # | 问题 | 当前处理 |
|---|------|----------|
| R1 | 食材单位换算复杂（斤/克/毫升/把/根） | V1 不强制换算，同单位才合并，跨单位并排提示 |
| R2 | 自由文本解析不全（「黄豆酱半盒」） | 解析失败进入待确认；后续可做常用别名规则表 |
| R3 | 两人家用无需登录，但远程暴露有风险 | 远程默认关闭；启用时用可选家庭口令 + 只读兜底 |
| R4 | 「一根葱」这类模糊量词 | 收录在单位表，原样参与同单位合并 |
| R5 | 手机浏览器字体小 | UI 阶段用大字号 + rem 适配 |

## 9. 验收口径（DoD）

每发布一个版本，必须同时满足：

- [ ] 核心链路 30 秒完成。
- [ ] 合并清单无重复食材（至少知名别名不重复）。
- [ ] 批量录入示例文本解析正确。
- [ ] 有自动化测试证明：备菜勾选前后库存快照一致。
- [ ] 月历能回看本月饭局与那句话。
- [ ] 局域网内手机 + 桌面均可访问。
